# PPF PROFI Growth Bot — v2 foundation

Отдельный Node.js сервис для Timeweb. Сайт Next.js не затрагивается самим процессом бота.

## Утверждённая политика
- Месячный предел: **30 000 ₽**.
- Дневной предел: **1 500 ₽**.
- Сайт: автономные изменения и публикация после прохождения проверок.
- Реклама: автономное управление выделенными рекламными кабинетами.
- Внешнее продвижение: самостоятельные публикации и адресные деловые предложения на разрешённых площадках.

Полномочия — это целевая политика. Реальные действия провайдеров включаются только после настройки соответствующих API и проверки интеграций. Пока credentials отсутствуют, внешние операции fail-closed и не выполняются.

## Реализовано в этой версии
- Telegram allowlist по одному разрешённому chat/user ID.
- Команды `/start`, `/help`, `/status`, `/budget`, `/pause`, `/resume`, `/scan`.
- Ежедневная техническая проверка сайта в 09:00 Europe/Moscow.
- Проверка главной, robots.txt, sitemap.xml и до 100 URL из sitemap.
- Политика расходов в `src/policy.mjs`.
- Бюджетный учёт с дневным и месячным ограничениями и резервированием средств в `src/budget.mjs`.
- Журнал действий JSONL в `src/audit.mjs`.
- Состояние бюджета и аудит хранятся в постоянном томе `/data`.
- Документированы контракты будущих интеграций.

## Что ещё НЕ подключено
- GitHub Actions / Timeweb production deploy.
- Яндекс Директ API.
- VK Ads API.
- Яндекс Метрика и Google Search Console API.
- Площадки для публикаций и CRM/реестр контактов.
- Автоматическая генерация и публикация контента.
- Реальное списание и сверка рекламных расходов с провайдерами.

Поэтому эта версия пока не запускает рекламу, не отправляет сообщения и не меняет production-сайт. Она готовит безопасную основу и Telegram-пульт. Не выдавать запланированные функции за работающие.

## Развёртывание
1. Node.js 22+ или Docker.
2. Создать отдельного Telegram-бота через @BotFather.
3. В Timeweb задать `TELEGRAM_BOT_TOKEN` и `TELEGRAM_ALLOWED_CHAT_ID` через секреты сервиса.
4. Подключить постоянный volume к `/data`.
5. Установить `SITE_URL=https://ppfprofi.ru`.
6. Запустить `npm run check`, затем `npm start`.
7. Проверить команды `/status`, `/budget`, `/scan`, `/pause`, `/resume`.

## Безопасность и правила запуска интеграций
- Не хранить секреты в Git и не отправлять их в чат.
- Для каждой интеграции — отдельный токен с минимальными правами.
- Перед любым платным действием обязателен бюджетный резерв; после подтверждения провайдера — сверка фактической суммы.
- Не запускать рекламу без настроенных целей конверсии, UTM и выделенного платёжного метода.
- Деплой только через отдельный production workflow с тестами, health-check и rollback; не выдавать агенту доступ к БД и секретам приложения.
- Outreach — только законные деловые контакты, разрешённые площадки, контроль частоты, стоп-лист и opt-out; никакого массового спама, скрейпинга личных адресов или обхода правил.
- Изменения цен, платёжных реквизитов, юридических условий и политики конфиденциальности требуют отдельного согласования.
- `/pause` — аварийная остановка; доступен только разрешённому Telegram ID.

## Проверки
Перед production необходимо выполнить `npm run check`, Docker build и тесты бюджета (месячный предел, дневной предел, резервирование, отмена, смена дня/месяца). В этой сессии runtime на Timeweb и реальные API не проверялись.
